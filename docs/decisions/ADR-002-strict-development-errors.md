# ADR-002：开发阶段使用严格错误，不生成技术兜底回应

- 状态：已确认
- 日期：2026-08-11
- 决策人：项目总工程师
- 替代：ADR-001 第 5 条中的通用确定性兜底

## 背景

模型超时、模型输出结构错误或引用不存在时，如果系统自动生成一条看起来正常的儿童回应，前端和测试人员会把失败误认为成功，问题会被延迟到真实体验阶段。

## 决策

1. 技术错误直接返回固定错误码、原始错误信息和校验问题。
2. 每次请求最多调用一次模型 Provider，不重试、不切换备用 Provider。
3. HTTP API 固定 4 秒超时；超时返回 `PROVIDER_TIMEOUT`。
4. 请求字段不允许通过 `值 A || 默认值` 补齐。
5. 走失、隐私输入和主动停止仍返回确定性安全回应，因为它们是业务规则，不是技术兜底。

## 结果

开发测试台会清晰展示失败。正式上线前是否增加面向儿童的网络错误界面，需要作为独立产品决策处理，不能在 Agent Core 内静默实现。
